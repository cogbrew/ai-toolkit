# 목적과 구성

## 목적을 먼저 정함
- 보고서의 목적을 먼저 한 줄로 정함. 예: 영향도 분석, 방안 검토, 결과 보고, 제안. 목적이 불분명하면 쓰기 전에 사용자에게 물음.
- 목적에 없는 내용은 넣지 않음. 영향도 분석 보고서에는 체크리스트, 전환 절차, 일정표 같은 실행 계획을 넣지 않음. 막는 실수: 보고서가 목적 둘을 동시에 하다가 어느 쪽도 결론에 닿지 못하는 일.
- 읽는 사람이 마지막에 답해야 할 질문 하나를 정하고, 그 질문에 답하지 않는 섹션은 빼거나 부록으로 보냄.

## 기본 흐름
요약, 배경, 현재 상황, 본론(분석이나 검토), 결론, 부록 순서임.

| 섹션 | 쓰는 것 |
|---|---|
| 요약 | 결론만 1~2줄. 본문 문장을 그대로 복사하지 않음 |
| 배경 | 왜 이 보고를 하게 됐는지만 짧게 |
| 현재 상황 | 구조, 제약, 데드라인. 데드라인은 왜 지켜야 하는지까지 씀 |
| 본론 | 보고서 성격에 맞는 하위 구성(아래 표) |
| 결론 | 판단과 근거를 표나 짧은 목록으로. 앞 내용을 반복하지 않고 요약 |
| 부록 | 실무자용 상세 내용. 분류한 목록 수준 |

- 앞 섹션이 다음 섹션의 이유가 되도록 이음. 결론이 갑자기 나오면 그 사이에 빠진 연결 고리(대개 현재 상황)를 채움.
- 실무자용 상세는 본문에 넣지 않고 부록에 둠. 막는 실수: 결정권자가 읽을 본문이 상세 때문에 길어지는 일.
- 결론을 낼 수 없으면 결론을 만들어 내지 않고 판단 유보 사유와 추가 확인할 것을 첫 부분에 씀(에이전트 추가, slop-rewrite 가이드라인의 같은 취지 규칙을 따름).

## 목적별 본론 구성
보고서 성격에 맞게 정하며 아래는 참고 예시임.

| 목적 | 본론 하위 구성 |
|---|---|
| 영향도 분석 | 영향 전파 경로, 주요 리스크, 사용자 영향 |
| 방안 검토 | 방안별 개요, 비교(장단점, 비용, 기간), 리스크 |
| 결과 보고 | 수행 내용, 결과와 지표, 이슈와 후속 조치 |

- 제안 보고서의 본론 구성은 옛 스킬에 없었음. 필요하면 사용자에게 구성 순서를 묻고 정해지면 이 표에 더함(미정).

## 겹치는 규칙의 기준
- 이 문서의 흐름은 분석과 검토형 보고서(영향도 분석, 방안 검토)를 기준으로 하며 요약을 맨 위에 둠. 결재용 의사결정 보고서나 상황보고처럼 유형별 순서가 정해진 경우 slop-rewrite 의 개조식 보고서 작성 가이드라인의 순서를 따름.
- 두 문서가 어긋나면 사용자가 지정한 서식, 이 스킬, 가이드라인 순으로 따름(에이전트 추가, 사용자 확인 필요).
