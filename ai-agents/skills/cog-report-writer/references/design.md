# 디자인

조직이나 참고 문서가 지정한 서식이 있으면 그것이 우선함. 참고 HTML 을 받으면 그 스타일을 우선함.

## 공통(모든 형식)
- 제목과 부제는 각각 한 줄로 씀.
- 상태 표시(검토 중)와 작성자, 근거 문구는 넣지 않음. 사용자가 요청할 때만 넣음.
- 굵은 글씨는 꼭 필요한 곳에만 씀. 막는 실수: 모든 곳이 강조되어 강조가 사라지는 일.
- 같은 성격의 목록과 표는 같은 모양으로 맞춤.
- 차분한 색 체계를 쓰고 색은 의미를 담을 때만 씀.
- 요약은 눈에 띄는 박스로 둠. 연회색 배경에 녹색 왼쪽 선을 씀.
- 판단 표시(불가, 조건부, 가능, 영향 없음)는 아래 색의 알약형 배지나 색 글자로 씀.
- 리스크는 관점 태그(기술, 비용, 운영)와 항목 목록으로 쓰고, 종합은 마지막에 빨강 계열로 강조함.
- 흐름은 같은 크기의 상자와 화살표로 그리고 상자 정렬을 맞춤. 화살표는 흐름도에만 씀.
- 완성한 뒤 실제 화면(렌더링이나 미리보기)에서 정렬과 줄바꿈을 확인함. 막는 실수: 코드로는 맞는데 화면에서 줄이 깨지는 일.

## 색 체계
| 용도 | 색 | 코드 |
|---|---|---|
| 본문 글자 | 진회색 | #172126 |
| 보조 글자 | 회색 | #5d6b70 |
| 구분선 | 연회색 | #dce4e2 |
| 포인트, 가능 | 녹색 | #176b52 (배경 #e2f1eb) |
| 기술, 대상 | 파랑 | #376b9b (배경 #eaf1f7) |
| 비용, 조건부 | 황색 | #b77319 (배경 #fbf1df) |
| 불가, 종합, 경고 | 빨강 | #b4413a (배경 #fbe9e7) |

- 색의 뜻은 보고서 전체에서 하나로 고정함. 같은 색을 다른 뜻에 쓰지 않음.
- 색만으로 뜻을 전하지 않고 글자(가능, 불가 등)를 함께 씀(에이전트 추가, 색각 이상 독자를 위한 일반 규칙).

## 형식별 적용
| 형식 | 적용 |
|---|---|
| HTML | `references/report-base.css` 를 씀 |
| 문서(Docs, Word) | 공통의 색과 구성을 표와 제목 스타일로 옮김. 요약은 음영 박스로, 판단은 색 글자로 씀 |
| 슬라이드 | 1장 1메시지로 씀. 첫 장에 요약을 두고 위 색 체계를 씀 |
| 채팅 답변과 Markdown | 색 없이 구성과 내용 규칙만 적용함 |

## HTML 기본 CSS
- 파일은 `references/report-base.css` 이며 옛 스킬의 CSS 를 그대로 가져온 것임. 클래스 이름(summary, grid, card, tbl, lv, flow, gitem, ritem, chips 등)은 이 CSS 안에서 정의됨.
- 클래스를 새로 만들기 전에 위 CSS 에 이미 있는지 확인함.
- 모바일(너비 700px 이하) 규칙이 들어 있으므로 좁은 화면에서도 확인함(에이전트 추가).
- 색 코드와 CSS 는 현재 렌더링으로 다시 확인한 것이 아님(미확인).
