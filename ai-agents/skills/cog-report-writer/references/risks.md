# 리스크와 이슈 작성 기준

리스크나 이슈를 다루는 보고서에만 적용함.

## 관점으로 나눔
기술, 비용, 운영 세 관점으로 나누고 항목마다 분류가 맞는지 다시 확인함. 막는 실수: 비용 문제가 기술 항목에 섞여 담당이 갈리는 일.

| 관점 | 담는 것 |
|---|---|
| 기술 | 시스템 구조상 안 되거나 바꿔야 하는 것 |
| 비용 | 기획과 개발 공수, 외주 비용, 투입 인력 |
| 운영 | 데이터와 권한 재설정 같은 운영 작업 |

## 항목 쓰는 법
- 검토 대상 때문에 새로 생기는 문제만 씀. 이미 있던 문제와 일시적인 이슈는 뺌.
- 비용 항목에는 왜 공수가 드는지 원인을 씀. 막는 실수: 공수 숫자만 있어 줄일 방법을 논의할 수 없는 일.
- 숫자에는 기준과 단위를 씀(예: 1인 기준 최소 6개월 이상).
- 항목은 기술 용어를 일반 독자도 알아듣게 풀어 씀(에이전트 정리, 옛 스킬의 문체 규칙에서 옮김).

## 종합
- 마지막에 종합을 두고 결론 1줄과 근거 1줄로 씀.
- 종합의 판단은 항목들의 근거와 서로 맞아야 함(항상 지킬 것 6번).
- 검증하지 않은 가정을 리스크 항목의 근거로 쓰지 않음(에이전트 추가).
