# cog-report-writer

보고서를 쓸 때 지키는 구성, 내용, 디자인 규칙. 각 규칙에는 막으려는 실수를 함께 적음. 결과물 형식(HTML, 문서, 슬라이드, 채팅 답변)과 관계없이 구성과 내용 규칙은 항상 적용하고, 디자인 규칙은 형식별로 적용함.

문체(개조식 명사형 종결, 어휘, 항목 길이, 제목 규칙)는 이 스킬이 정하지 않고 slop-rewrite 스킬의 개조식 보고서 작성 가이드라인이 정함. 보고서를 다 쓴 뒤 개조식 검토나 윤문이 필요하면 slop-rewrite 로 넘김. 독자가 조직 밖이면 명사형 종결을 쓰지 않는다는 그 가이드라인의 예외도 따름.

## 항상 지킬 것
1. 쓰기 전에 보고서의 목적을 정하고 목적에 없는 내용을 넣지 않음. 막는 실수: 영향도 분석 보고서에 체크리스트와 전환 절차 같은 실행 계획이 섞이는 일.
2. 맨 위에 결론만 1~2줄로 요약을 두고 본문 문장을 그대로 복사하지 않음. 막는 실수: 요약이 본문의 반복이 되어 읽을 이유가 없어지는 일.
3. 앞 섹션이 다음 섹션의 이유가 되도록 이음. 결론이 갑자기 나오면 빠진 연결 고리를 채움. 막는 실수: 근거 없이 결론만 서 있는 보고서.
4. 리스크와 이슈는 검토 대상 때문에 새로 생기는 문제만 씀. 이미 있던 문제와 일시적인 이슈는 뺌. 막는 실수: 검토 대상과 무관한 문제가 판단을 흐리는 일.
5. 숫자에는 기준과 단위를 씀(예: 1인 기준 최소 6개월 이상). 막는 실수: 기준 없는 숫자가 사람마다 다르게 읽히는 일.
6. 판단과 근거가 서로 맞게 씀. 근거가 가능하나 일정상 불가이면 판단도 일정상 불가로 씀. 결론은 이것만 가능 식으로 단정하지 않음. 막는 실수: 근거와 판단이 어긋나 신뢰를 잃는 일.
7. 같은 대상은 문서 전체에서 같은 이름으로 씀. 막는 실수: 이름이 달라 다른 대상으로 읽히는 일.
8. 실명, 실제 아이디, 이메일, 사번 같은 개인을 특정하는 예시를 쓰지 않음. 막는 실수: 개인정보가 보고서와 함께 퍼지는 일.
9. 날짜를 기준으로 계산한 값(잔여 기간 등)은 보고 시점에 다시 확인함. 막는 실수: 작성 때 맞던 숫자가 보고 때 틀리는 일.
10. 자료에 없는 사실과 숫자를 지어내지 않고, 근거가 없으면 확인 필요로 남김. 막는 실수: 그럴듯한 가짜 근거가 결론을 받치는 일.

## 무엇을 읽을지
| 상황 | 읽을 파일 |
|---|---|
| 목적 정하기, 섹션 흐름, 목적별 본론 구성, 요약과 결론과 부록 | `references/composition.md` |
| 리스크와 이슈 항목 쓰기, 관점 분류, 종합 | `references/risks.md` |
| 색, 배지, 요약 박스, 형식별(HTML, 문서, 슬라이드, 채팅) 적용 | `references/design.md` |
| HTML 보고서를 만들 때 쓰는 기본 CSS | `references/report-base.css` |

## 이 스킬에 두지 않는 것
- 문장 윤문, AI 티 검토, 개조식 종결과 어휘와 항목 길이, 제목 규칙은 slop-rewrite 스킬이 함
- 상황보고, 회의결과, 정책기획 같은 유형별 옆제목 순서와 분량은 slop-rewrite 의 개조식 보고서 작성 가이드라인이 정함
- 조직이 지정한 서식이 있으면 그 서식이 이 스킬의 디자인 규칙보다 우선함
