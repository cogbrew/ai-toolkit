# cog-vue

Vue 3 + Vite SPA 에서 Pinia 와 @nuxt/ui 로 화면을 만들 때 지키는 기본 규칙. 각 규칙에는 막으려는 실수를 함께 적음. 라이브러리 버전은 프로젝트의 package.json 이 정함. Nuxt 가 아니므로 Nuxt 문서의 NuxtPage 는 RouterView 로, NuxtLayout 은 라우트 component 로, 파일 기반 라우팅은 router/routes.ts 로 바꿔 읽음.

예시의 App* 컴포넌트와 use* 컴포저블(AppDataTable, useListQuery, useResultToast 등)은 예시를 가져온 프로젝트의 공용 부품임. 다른 저장소에서는 같은 일을 하는 부품에 같은 규칙을 적용함.

## 항상 지킬 것
1. 앱(apps/A)은 다른 앱(apps/B)을 임포트하지 않음. 임포트하고 싶어지면 전역으로 올릴 것인지 묻는 때임. 막는 실수: 앱을 지울 때 다른 앱이 깨지는 숨은 의존.
2. 서버 호출(HTTP)은 스토어만 하고 화면과 컴포저블은 직접 부르지 않음. 막는 실수: 실패 처리가 화면마다 달라지는 일.
3. 스토어는 Setup Store 로만 만들고, 페이지를 떠날 때 그 페이지의 스토어를 되돌림. 막는 실수: 이전 화면의 상태가 다음 진입에 남는 일.
4. 파일 최상단에서 useStore() 를 부르지 않고 콜백 안에서 부름. 막는 실수: Pinia 설치 전에 호출되어 터지는 일.
5. 임포트는 별칭 절대경로(@/)만 쓰고 상대경로를 쓰지 않음. 막는 실수: 디렉토리를 옮길 때 참조가 깨지는 일.
6. 컴포저블에 넘기는 값은 그 호출보다 위에서 선언함. 막는 실수: TDZ 로 화면이 통째로 비고 콘솔에만 ReferenceError 가 남는 일.
7. 앱 안의 컴포넌트와 전역 컴포넌트는 모두 직접 임포트함(Nuxt UI 의 컴포넌트와 컴포저블만 자동 임포트). 막는 실수: 임포트 없이 쓴 컴포넌트가 에러 없이 안 그려지는 일.
8. 색은 시맨틱 토큰(text-muted, bg-elevated)만 쓰고 숫자 스케일(text-neutral-500)과 dark: 수동 지정을 쓰지 않음. 막는 실수: 다크 모드에서 색이 전환되지 않는 일.
9. 여백과 크기에 대괄호 임의값(w-[380px])을 쓰지 않고 4px 배수 클래스를 씀. 막는 실수: 스케일에서 벗어난 값이 화면마다 쌓이는 일.
10. 아이콘은 한 컬렉션만 쓰고 저장하는 아이콘 이름에는 굵기 꼬리표를 붙이지 않음. 막는 실수: 없는 이름이 되어 아이콘이 조용히 안 그려지는 일.
11. 레이아웃 트랙을 섞지 않음. UDashboardGroup 안에서는 UHeader 가 아니라 UDashboardNavbar 를 씀. 막는 실수: 두 트랙의 높이와 고정 배치가 충돌하는 일.
12. 환경변수는 VITE_ 로 시작하는 것만 코드에 노출되며 비밀 값을 넣지 않음. .env 는 커밋하지 않고 에이전트는 .env 값을 읽거나 출력하지 않음. 막는 실수: 빌드 결과물에 비밀 값이 들어가는 일.

## 이 스킬에 두지 않는 것
- 데이터 테이블, 읽기 전용 상세, 페이지 헤더, 토스트와 모달 흐름, 폼 검증 같은 화면 패턴(후속 스킬 후보)
- @nuxt/ui 컴포넌트 자체의 API 와 선택 기준(설치되어 있으면 nuxt-ui 스킬을 따로 읽음)
- 스택과 무관한 코드 규칙은 `cog-code-writer`, 서버가 줄 필드나 API 모양을 바꾸는 일은 `cog-django`
- 저장소가 지금 어떻게 생겼는지(구조 현황, 명령, 브랜드 팔레트, 백엔드 계약)는 규칙이 아니라 그 저장소의 문서에 둠
