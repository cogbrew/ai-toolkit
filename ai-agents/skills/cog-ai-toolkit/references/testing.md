# 시험 방법

Claude 기준이고 2026-11-11 에 확인한 옵션이다. 버전에 따라 달라질 수 있다.

- 지침 따름 시험: 스크래치패드에 빈 폴더를 만들고 시험할 지침을 그 폴더의 `CLAUDE.md` 로 둔다. `claude -p` 로 실행하고, 전역 `CLAUDE.md` 는 `--settings` 의 `claudeMdExcludes` 로 제외하며, 도구는 `--tools ""` 로 끈다.
- 로드 확인은 「지침을 인용해 보라」가 아니라 표식 문장(임의의 암구호)으로 한다. 인용 요청은 믿을 수 없었다.
- 서브에이전트(Agent 도구)는 시험에 쓰지 않는다. 전역 지침을 물려받아 시험이 오염된다.
- 도구를 끄면 「확인 후 답변」 규칙 때문에 안을 내지 않는다. 시험 과제에 필요한 내용을 프롬프트에 넣는다.
- 조직 관리자 지침은 제외되지 않는다.
- 스킬 호출 시험: 본문이 확인 문구 한 줄인 껍데기 스킬로 `description` 만 바꿔 호출 여부를 본다. 스킬은 도구로 불리므로 도구를 끄지 않는다. 응답 전체가 확인 문구 한 줄일 때만 호출로 센다. 응답이 문구를 인용만 한 것은 호출이 아니다.
- 스킬 직접 호출 시험: 시험 프로젝트의 `.claude/skills/` 에 스킬 폴더를 링크로 걸고 `claude -p` 에 `/스킬이름 …` 요청을 보낸다. `--output-format stream-json --verbose` 로 도구 호출 기록을 받아 `SKILL.md` 와 `references/` 를 읽었는지 확인한다. `--add-dir` 은 값을 여러 개 받으므로 질문을 표준 입력으로 넘긴다.
- 문서 읽음 시험: 문서 안에 「응답 첫 줄에 표식을 쓴다」는 규칙을 두고 표식이 나오는지 본다. 응답이 쓰기 실패 안내로 시작하면 표식이 첫 줄에 없어도 문서를 읽은 경우가 있으므로, 응답에 문서 이름이 언급됐는지도 함께 본다.
- 방식 비교 시험: 같은 과제를 네 조건(스킬만, 스킬과 지침 한 줄, 규칙 직접, 아무것도 없음)의 시험 프로젝트에서 `claude -p` 로 돌린다. `--output-format stream-json --verbose` 기록에서 `Skill` 도구 호출을 세어 호출률을 구하고, 동작은 결과물(독스트링 수, 목업 이름, 확인 항목 언급)로 본다. 변별하지 못하는 과제는 결론에서 뺀다.
- 전역에 옛 스킬이 남아 있으면 시험이 오염된다. 아무것도 없는 조건에서도 옛 스킬이 호출된다. `--disallowedTools "Skill(이름)"` 으로 옛 스킬을 막고, 기록에서 옛 스킬의 시도 수와 실행 수를 따로 세어 차단을 확인한다. 막아도 에이전트는 호출을 시도하므로 시도는 남는다.
- 질문당 1~3회 실행하므로 한 번의 차이로 결론을 내지 않는다.
- 연결 스크립트 시험: `HOME` 을 스크래치패드의 가짜 홈 폴더로 바꿔 계획 출력, `--apply`, 재실행, `--backup` 을 차례로 돌려 링크, 기존 항목 보존, 멱등성을 확인한다. 실제 홈 폴더에는 `--apply` 를 쓰지 않는다. 2026-11-11 에 이 방식으로 시험했다.
- 비대화형 시험에서 작업 폴더 밖 읽기와 `python` 실행은 승인이 필요하다. 시험에서는 `--add-dir` 와 `--allowedTools` 로 허용한다. 전역 링크(`~/.claude/skills/<스킬>`)를 거치는 스킬은 링크가 있는 폴더(`~/.claude/skills`)와 링크가 가리키는 저장소 위치 둘 다 `--add-dir` 로 열어야 읽힌다. 하나만 열면 거부된다. 대화형 세션에서는 승인 창으로 허용할 수 있고, 2026-11-11 대화형 세션에서는 `cog-ai-toolkit` 의 `references/` 읽기가 승인 없이 통과했다(1회 관찰).
- 시험 스크립트에 재귀 삭제 같은 위험 명령을 쓰지 않는다. 새로 만드는 시험 폴더는 지울 필요가 없다.
- Codex(`codex exec`)와 Antigravity(`agy -p`) 시험은 사용자가 환경을 준비해 준 뒤에만 한다.
