# 스킬을 만들거나 고칠 때

## 가져온 스킬을 추가하는 절차

1. 가져온 프로젝트를 `ai-agents/skills/<스킬 이름>/project/` 에 내부 구조 그대로 복사한다.
2. 스킬 안의 인수 테스트가 있으면 새 위치에서 돌려 통과를 확인한다. `slop-rewrite` 는 `ai-agents/skills/slop-rewrite/project` 에서 `python3 -X utf8 .claude/skills/slop-rewrite/tests/run_acceptance.py` 로 돌린다.
3. `ai-agents/skills/<스킬 이름>/SKILL.md` 진입 파일을 만든다. 형식은 아래 「진입 파일 형식」을 따른다.
4. 전역 연결(심볼릭 링크)은 사용자가 `scripts/install_ai-toolkit.sh --apply` 로 한다. 에이전트는 `--apply` 를 실행하지 않는다. 옵션 없이 실행하면 계획만 출력하므로 에이전트도 실행할 수 있다.

가져온 스킬이 표준 형식(폴더 바로 아래에 `SKILL.md` 가 있는 것)이면 래퍼 폴더 없이 `ai-agents/skills/<스킬 이름>/` 에 그대로 두고 3번은 건너뛴다.

### 진입 파일 형식

```
---
name: <스킬 이름>
description: <언제 이 스킬을 쓰는지와 트리거 문구>
---
본체는 이 폴더의 `project/<본체 SKILL.md 상대 경로>` 다. 그 파일을 읽고 따르며, 본체가 말하는 「프로젝트 루트」는 이 폴더의 `project/` 이고 상대 경로 명령은 거기서 돌린다. 원칙·스타일가이드·취향은 `project/` 안의 것을 쓴다.
```

- 경로는 모두 이 폴더 기준 상대경로로 쓴다. 사용자 이름이 든 절대경로는 쓰지 않는다.
- Claude·Codex·Antigravity 가 같은 `SKILL.md` 형식을 읽으므로 진입 파일은 도구마다 두지 않고 한 벌만 둔다.

## 직접 만드는 스킬의 작성 기준

직접 만드는 스킬에 적용한다. 가져온 스킬(`slop-rewrite` 등)은 내부 구조를 바꾸지 않는다.

- 작성 도구: Claude 의 `skill-creator` 스킬을 이름으로 호출한다. 가져온 스킬에는 쓰지 않는다(폴더 구조를 바꾸기 때문). 경로에 해시가 있어 경로는 적지 않는다.
- 형식: `SKILL.md` 머리말의 `name`·`description` 만으로 세 도구가 읽는다. `name` 은 폴더 이름과 같게 둔다.
- 이름: 직접 만드는 스킬의 폴더 이름과 `name` 은 `cog-` 로 시작하는 소문자-하이픈으로 정한다. 가져온 스킬은 이름을 바꾸지 않으며, 접두사가 없으면 가져온 스킬이다.
- `description`: 무엇을 하는지, 언제 쓰는지, 쓰지 않는 경우를 쓴다. 핵심 용도와 사용자가 쓸 법한 키워드를 앞에 둔다.
  - Claude 는 목록에서 1,536자까지만 보여 준다.
  - Codex 는 목록 예산(컨텍스트의 2% 또는 8,000자)을 넘으면 설명부터 줄인다.
  - Antigravity 는 3인칭을 권한다.
- 본문: Claude 기준 500줄 이하. 상세 자료는 `references/` 로 나누고 본문에 언제 읽을지 적는다. 스킬 하나는 한 가지 일만 한다.
- 문체: 규칙은 명사형 종결(개조식)로 쓰고, 각 규칙에 막으려는 실수를 함께 적는다. 강한 금지어보다 이유를 설명한다. 특수기호(절 기호, 화살표, 줄표, 이모지)를 쓰지 않는다.
- 점검: 윤문 검사기(`slop-rewrite` 의 `check_all.py --guide 개조식 <파일>`)를 파일마다 돌려 원칙 층(AI 티) 결과를 본다. 장르 층의 제목·개요·수치 근거 지적은 보고서용이라 스킬 문서에 적용하지 않는다. 오탐은 근거를 밝히고 넘긴다. 예: 일반 동사 「있어서」를 번역투로 잡은 경우.
- 전역 연결: 래퍼 폴더의 진입 파일에는 `name`, `description`, `project/` 를 가리키는 상대경로만 둔다. 전역 에이전트가 읽는 것은 진입 파일의 `description` 이므로 본체의 모드와 제외 조건을 거기에 담는다. 본체 모드를 넣은 `description` 이 호출을 늘렸다(Claude, 1회 시험).
- 시험: 호출되어야 할 질문과 호출되면 안 되는 질문을 목록으로 만들어 호출 여부를 본다(`testing.md`).

## 규칙으로 둘지 스킬로 둘지

코드를 쓸 때마다 적용돼야 하는 규칙처럼 모든 작업에서 반드시 읽혀야 하는 내용에 쓰는 기준이다.

- 스킬만 두면 `description` 으로 자동 호출된다. `cog-code-writer` 시험(Claude, 코드 작성 요청 10개)에서 8개만 호출됐다. 짧은 함수 추가와 목업 데이터 작성처럼 규칙이 필요한 작업으로 보지 않는 요청에서 놓쳤다.
- 스킬을 두고 전역 지침(`ai-agents/AGENTS.md`)에 「작업 전에 이 스킬을 먼저 호출함」 한 줄을 더하면 10개 모두 호출됐다. 이 방식을 쓴다.
- 규칙 본문을 지침에 직접 넣는 방식도 규칙은 지켜졌지만, 같은 규칙이 지침과 스킬 두 곳에 생겨 한쪽만 고치다 어긋난다. 세부와 예시도 담기지 않는다.
- 규칙이 지켜지는지는 같은 과제를 네 조건(스킬만, 스킬과 지침 한 줄, 규칙 직접, 아무것도 없음)으로 돌려 견준다(`testing.md`).
