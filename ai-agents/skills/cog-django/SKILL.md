# cog-django

Django 와 DRF 로 백엔드를 만들 때 지키는 기본 구성 규칙. 각 규칙에는 막으려는 실수를 함께 적음. 버전은 프로젝트의 requirements.txt 가 정함.

## 항상 지킬 것
1. 앱은 서로 임포트하지 않음. 임포트하고 싶어지는 순간이 기반 계층(accounts, core, utils)에 있어야 할 것인지 묻는 때임. 막는 실수: 앱 사이 순환 참조와 앱 경계 붕괴.
2. 환경변수는 설정 계층(config, 모듈의 config, 진입 파일)에서만 읽고 앱 코드에서 os.getenv 를 부르지 않음. 막는 실수: 설정이 코드 곳곳에 흩어져 어디서 바뀌는지 알 수 없는 상태.
3. 필수 환경변수는 기본값 없이 부팅 때 한 번에 검사함. 막는 실수: 빠진 변수가 운영에서 늦게 터지는 일.
4. .env 는 커밋하지 않고 값 없는 틀인 .env.example 만 커밋함. 에이전트는 .env 값을 읽거나 출력하는 명령을 쓰지 않음. 막는 실수: 비밀 값 유출.
5. 새 앱, 새 로거, 새 관리 커맨드는 등록 위치에 직접 등록함. 막는 실수: 404 가 나거나 로그가 소리 없이 사라지는 일.
6. 패키지를 설치하면 같은 작업에서 requirements.txt 에 추가함. 막는 실수: 새 환경에서 부팅이 실패하는 일.
7. 테스트는 운영과 같은 DB 로 돌림. 막는 실수: SQLite 에서만 통과하는 거짓 초록불. 예를 들어 MySQL 이 지원하지 않는 조건부 유니크.
8. Django 기본값과 다르게 둔 설정은 이유를 적음. 막는 실수: 이유를 모르는 설정을 정리하다가 지우는 일.
9. 데이터를 버리거나 판단을 바꾸는 분기에는 경고와 식별자를 함께 남김. 막는 실수: 몇 건인지만 알고 누구를 고쳐야 할지 모르는 상태.

## 이 스킬에 두지 않는 것
- 인증과 권한 체계(로컬, SAML, OIDC), 배치와 외부 연동 설계, DRF API 설계(선택지, 시리얼라이저, 오류 위치), 프론트엔드
- 저장소가 지금 어떻게 생겼는지(구조 현황, 열린 API, 명령)는 규칙이 아니라 그 저장소의 문서에 둠
