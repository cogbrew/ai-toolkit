# 화면 패턴의 공통 원칙

프레임워크와 무관한 규칙. 부품 이름은 예시 프로젝트의 것이며, 구현 방법은 `frameworks/<라이브러리>/` 에 있음.

## 부품의 역할
| 역할 | 예시 부품 | 맡는 일 |
|---|---|---|
| 페이지 헤더 | AppPageHeader | 제목과 부제. 메뉴 데이터에서 스스로 찾음 |
| 툴바 | AppPageToolbar | 왼쪽에 검색과 필터, 오른쪽에 선택 액션 |
| 목록 필터 | AppListFilters | 검색창과 필터 셀렉트 |
| 표 | AppDataTable | 표 껍데기(테두리, 최소 높이, 빈 문구, 정렬 헤더, 선택 체크박스) |
| 목록 | AppDataList | 줄 높이가 같은 목록(가상 스크롤, 바닥 감지, 다시 시도) |
| 페이지네이션 | AppPagination | 건수 줄과 페이지 이동 |
| 확인 모달 | AppConfirmModal | 파괴적 행위 확인 |
| 상세 | AppDetailSection, AppDetailItem, AppDetailTile | 섹션 제목, 라벨과 값 한 칸, 건수 타일 |
| 가져오기 상태 | AppFetchState | 스피너, 실패와 다시 시도, 본문 |
| 조회 컴포저블 | useListQuery, useListFetch, useListSelection | 조건, 결과, 선택 |
| 상세 컴포저블 | useDetailFetch | 한 건 가져오기 상태 |
| 알림 | useResultToast | 토스트 래퍼 |

## 목록
- 조건(useListQuery), 결과(useListFetch), 선택(useListSelection)은 각각 한 가지만 하고 페이지가 세 줄로 이음. 이음새는 listQuery 와 page 뿐임. 툴바와 표와 페이지네이션과 생성 버튼을 함께 품는 것이 페이지이므로 페이지가 조회 컴포저블을 부름.
- 표는 `<가족>Table` 로 따로 뺌. 컬럼과 셀 슬롯과 행을 눌러 여는 모달이 그 안에 있고, 페이지는 rows, loading, error 를 props 로, sorting 과 rowSelection 을 v-model 로 넘김.
- 모달은 결과('saved')를 돌려주고 표가 이를 올리면 페이지가 refresh 를 부름.
- 화면마다 새로 쓰는 것은 컬럼 정의, 필터 선언(3줄이면 화면 안에), 스토어 액션 셋뿐임.
- 조회 배선은 컴포저블이 갖고 화면이 watcher 를 직접 엮지 않음. 검색 디바운스, 조건이 바뀌면 1페이지로 되돌리기, 정렬을 서버 파라미터로 바꾸기, 요청 순서 보장이 컴포저블 안에 있음.
- URL 이 아니라 스토어 액션을 컴포저블에 넘김.
- 필터는 key 와 라벨만 선언하고 선택지는 서버가 줌. 화면은 필터가 몇 개든 선언 한 줄만 늘어남.
- 정렬 가능 필드 목록을 프론트에 따로 두지 않음. 헤더를 단 컬럼이 곧 백엔드가 허용한 정렬 필드임. 막는 실수: 허용되지 않은 필드로 정렬을 보내면 서버가 에러 없이 버려 헤더는 눌리는데 순서가 안 바뀌는 일.
- 조회 조건은 computed 하나(listQuery)이고 재료를 따로 감시하지 않고 결과를 감시함. listQuery 에 page 를 넣지 않음(무한 스크롤이 같은 listQuery 를 받기 위함).
- 요청은 한 곳(watch 한 개)에서만 나가고, 조건이 바뀌면 1페이지로 돌리기만 함. 두 watch 는 조건, 결과 순서로 선언함. 막는 실수: 순서가 뒤집혀 같은 틱에 요청이 두 번 나가는 일.
- 선택은 id 가 아니라 행 객체로 돌려줌. 막는 실수: 다른 페이지에서 고른 행의 내용을 몰라 확인 모달이 무엇을 지우는지 말할 수 없는 일.
- HTTP 래퍼에 요청 취소나 순서 보장이 없으면 시퀀스 토큰으로 늦은 응답을 버리고 loading 은 마지막 요청이 끝날 때만 끔. 막는 실수: 정렬을 연달아 누를 때 늦게 온 응답이 화면을 덮고 먼저 끝난 요청이 스피너를 끄는 일.
- 공용 목록 컴포저블은 검색, 필터, 정렬을 기본으로 갖춤. 지금 쓰는 화면이 없다고 걷어내지 않음. 같은 기본 기능이 두 컴포저블에 겹치면 걷지 않고 한곳으로 모으자고 제안함.
- 빈 목록 문구는 하나이고 검색 결과가 없는 경우와 원래 없는 경우를 가르지 않음. 안내나 사유를 말해야 하는 자리만 따로 적음.
- 표에는 최소 높이가 필요함. 없으면 창 높이를 줄일 때 본문이 0행까지 줄어듦. 페이지가 아니라 표에 걸고, 헤더와 4행과 빈 상태가 안 잘리는 눈금으로 잡음. 페이지 바닥 최소 높이는 앱 셸이 따로 통제함.
- 표마다 최대 높이를 재서 정하고 같은 값을 돌려 쓰지 않음. 다음 행이 절반쯤 보이는 높이를 골라 더 있다는 것이 드러나게 함.
- 열 순서는 사람이 찾아 들어가는 순서로 정하고 코드가 편한 순서로 정하지 않음. 열 머리도 사람이 읽는 말로 씀.
- 컬럼에는 문자열 header 만 줌. 표가 문자열을 정렬 헤더로 감싸고, 정렬을 막을 컬럼은 정식 옵션으로 막음. 셀 표현을 컴포넌트로 만들지 않고 빈 값이나 날짜는 순수 함수 포매터를 컬럼에서 직접 부름. 빈 값을 가질 수 있는 컬럼마다 cell 을 직접 담.
- 만들고 지운 뒤에 페이지를 옮기지 않음. 생성도 삭제도 현재 페이지를 그대로 다시 받고 필터, 검색, 정렬은 건드리지 않음. 생성을 1페이지로 보내고 싶어지지만 정렬이나 필터에 따라 새 행이 1페이지에 없을 수 있어 얻는 것이 없음.
- 지운 뒤 그 페이지가 없어지면(서버가 404 를 줌) 한 칸만 물러남. 1페이지로 튀지 않고, count 로 마지막 페이지를 미리 계산하지 않음(남이 지운 경우도 404 처리가 남으므로 길이 둘이 됨).
- 행을 눌러 여는 동작은 쓰는 화면에서만 켬. 함수 prop 이 있으면 켜고 없으면 끔. 키보드로 못 여는 한계가 있으면 알려 둠.
- 행 안에서 동작 하나를 바로 할 때(상세 없이)는 행 클릭 대신 맨 끝 칸에 버튼을 둠. 행 클릭과 같이 쓰지 않음(한 행에 진입로가 둘이 됨). 버튼 글자는 짧게, 제목은 비움. 권한이 없거나 반드시 실패할 행이면 숨김.
- 좁은 목록 패널(분할 화면의 왼쪽)에서 필터 셀렉트가 한 줄에 안 들어가면 셀렉트를 줄이지 않고 필터 버튼 하나와 팝오버로 넣고 고른 값은 칩으로 보임. 버튼에 개수 뱃지를 달지 않고 초기화 버튼도 두지 않음. 짝 필터는 앞의 것을 풀면 뒤의 것도 풀고 칩은 하나로 합침.

## 선택지
- 필터용 선택지(지금 데이터에 있는 값)와 폼용 선택지(고를 수 있는 값 전체)는 다른 목록임. 하나로 합치면 첫 사용자를 만들 때 목록이 비어 있음.
- 목록은 셀렉트를 열 때 받고 한 번 받으면 다시 받지 않음. 폼을 열자마자 모두 받지 않음.
- 선택된 값은 목록 없이도 그려져야 함. 상세에서 받은 값과 라벨 짝을 초기 선택지로 넣어 둠(seed). 막는 실수: 값은 있는데 화면이 비어 보여 사용자가 아무것도 안 골랐다고 생각하고 저장하는 일. 서버가 값과 라벨을 짝으로 줄 때만 가능함. 초기 선택지의 라벨은 목록의 라벨과 같은 모양이어야 함.
- 목록을 받았는데 지금 값이 없으면 비움(여러 개면 없는 것만 뺌). 라벨 하나를 위해 목록 전체를 미리 받지 않음.
- 여러 개를 고르는 셀렉트에는 한 번에 비우는 기능을 줌.
- 서버가 거른 검색 결과를 화면이 또 거르지 않음. 서버 검색을 쓰면 컴포넌트의 기본 필터를 끔. 막는 실수: 사번으로 찾은 사람이 라벨만 보는 화면 필터에 걸러져 사라지는 일.
- 셀렉트 하나마다 인스턴스를 만들지 않고 이름을 키로 받는 하나가 전부를 맡음(options.bind(name)). bind 는 같은 이름에 늘 같은 객체를 돌려줌. 막는 실수: 렌더마다 새 객체를 만들어 셀렉트가 매번 다시 그려지는 일.

## 읽기 전용 상세
- 서버가 주는 키를 아는 화면은 배열로 돌리지 않고 템플릿에 칸을 한 칸씩 씀. 키를 모르는 데이터(스냅샷, 변경 이력)만 루프와 라벨 사전으로 그림. 막는 실수: 화면에 무엇이 나오는지 보려고 computed 를 읽어야 하는 일.
- 켜짐과 꺼짐은 뱃지가 아니라 글자로 씀(IDP 또는 로컬, 활성 또는 비활성). 목록은 수백 줄에서 골라내야 해서 색이 일을 하지만 상세는 한 건이라 라벨이 이미 뜻을 말함. 잠근 스위치도 쓰지 않음.
- 같은 라벨이 두 곳 이상에 나오면 사전에서 가져오고, 한 곳만 쓰는 동안은 템플릿에 직접 적음.
- 라벨은 위, 값은 아래로 세로로 쌓음. 한 행에 쌍을 여럿 놓을 때 가로로 놓으면 값 바로 옆에 다음 라벨이 와서 눈이 잘못 묶음. 크기가 라벨과 값을 가르도록 라벨을 한 단계 작게 둠. 한 행에 한 쌍일 때만 가로가 맞음.
- 열 수는 가장 긴 값이 한 칸에 들어가는지 재서 정함. 긴 값만 두 칸을 씀. 꺾였는지는 눈이 아니라 줄 수(높이를 줄 높이로 나눔)로 봄. 내용이 찬 상태로 잼.
- 두 칸을 쓰는 칸은 칸 수를 하나 늘린 것과 같아 마지막 줄에 한 칸이 혼자 남을 수 있음. 칸은 중요한 순서로 늘어놓음.
- 수정 폼에 있는 칸은 폼 순서를 따르되 이어 읽히는 칸끼리 붙임.
- 늘 비는 칸도 v-if 로 숨기지 않음. 숨기면 당겨져 줄이 흐트러짐. 갈래가 다르다고 상세 모달을 나누지도 않음(수정 모달을 나누는 이유가 상세에는 없음).
- 서버가 이름을 주지 않는 코드(ACTIVE 등)를 화면에서 번역하지 않음. 한글로 보이려면 값을 준 시스템에 공식 이름이 있는지 확인하고 있으면 서버가 이름 칸으로 줌.
- 갈래별 건수는 타일로 셈. 숫자가 라벨보다 크고, 막대로 그리지 않음. 겹칠 수 있는 갈래끼리의 합계를 만들지 않음(겹치지 않는 분류끼리는 더해도 됨). 갈래마다 색을 칠하지 않고 한 칸만 다르게 두지 않음. 0을 지우지 않음(자리가 움직이면 이력끼리 비교가 안 됨). 숫자에 색을 입히지 않음.
- 표 한 칸에 여러 항목을 담을 때 라벨은 폭을 고정한 뱃지, 값은 일반 텍스트로 둠. 폭은 가장 긴 라벨을 재서 정하고, 값에는 색을 입히지 않음(글자 대비가 기준에 못 미치고 내용보다 색이 먼저 눈에 옴).
- 전후 값은 줄을 나눔. 이전은 흐린 글자, 이후는 화살표를 붙여 내어쓰기로 쓰고 이전 줄에는 들여쓰기를 주지 않음. 줄바꿈이 필요한 값은 줄바꿈을 보존하는 스타일을 줌.

## 페이지 헤더와 액션
- 제목과 부제는 화면에 적지 않고 라우트 메타로 메뉴를 찾아 그 이름과 설명을 씀. 찾는 일은 헤더 부품이 스스로 하고 화면은 헤더만 둠. 막는 실수: 관리 화면에서 메뉴를 고쳐도 페이지가 따라오지 않는 일. 부제가 제목의 동어반복이면 두지 않음.
- 부제는 산문이 아니라 제목에 붙는 한 줄 보조 라벨이므로 본문 크기를 주지 않음. 데이터가 주인공인 화면에서 안내문이 두 번째로 큰 글자가 되면 위계가 뒤집힘.
- 전역 헤더는 로고, 메뉴, 다크 모드, 로그아웃 전용이고 페이지 동작을 두지 않음.
- 액션은 성격으로 갈라 담음. 제목 줄 오른쪽에는 상시 켜져 있는 페이지 동작(생성, 실행), 검색과 필터 줄 오른쪽에는 고른 것에 하는 동작(선택 해제, 선택 삭제)을 둠. 상시 버튼을 툴바에 두면 줄이 흔들림.
- 버튼이 실제로 생길 때 마크업을 넣고 빈 껍데기를 미리 만들지 않음.
- 건수는 좌측 하단(페이지네이션 줄), 검색과 필터는 좌측 상단에 둠. 페이지네이션이 없는 목록 패널은 패널 제목 줄 오른쪽에 둠. 항목이 몇 개뿐인 목록에는 건수를 두지 않음. 제목 옆 괄호나 칩 줄 맨 앞에 두지 않음. 건수 단위는 건이고 총을 붙이지 않으며 숫자와 단위 사이를 띄우고 로캘을 명시한 천단위 구분자를 씀.
- 크기는 놓인 표면이 아니라 역할이 정함. 메뉴 팝업의 검색창은 목록 화면의 필터와 역할이 같아 같은 값임.
- 열은 두 겹으로 세우지 않음(바깥 그리드와 안쪽 그리드가 모두 1열이면 항목이 과하게 늘어남). 패널 폭은 상태에 따라 바꾸지 않고 고정한 채 열 수로 채움.

## 알림과 실패 표시
| 상황 | 수단 |
|---|---|
| 액션 결과(성공, 실패) | 토스트 |
| 페이지 안의 맥락 경고와 안내 | 인라인 알림 |
| 파괴적 행위 확인 | 확인 모달 |

| 실패 | 어디에 |
|---|---|
| 목록 조회 | 표 자리에 인라인과 다시 시도(토스트는 사라지면 빈 표만 남음) |
| 선택지와 공용 딕셔너리 조회 | 토스트(스토어가 띄움. 여러 화면이 반복해서 부르는 공용 호출만 허용하는 원칙의 예외) |
| 폼 제출 | 서버가 준 필드 에러를 그 필드에 붙임 |

- 확인 모달의 실패는 모달 안에서 말하고 토스트를 겹쳐 띄우지 않음. 모달 안에서 성공하면 토스트를 띄우고 모달을 닫음.
- 토스트는 공용 래퍼 하나로만 띄움. 제목은 무엇을 못 했나(호출부가 줌), 설명은 왜 못 했나(서버가 준 사유)임. 실패의 설명을 호출부가 손으로 쓰지 않음. 성공과 부분 실패를 한 줄로 뭉개지 않고 갈라서 부름.
- 실패 사유 문장은 HTTP 래퍼가 에러 객체를 만들 때 한 번 정함. 서버가 준 메시지를 그대로 담고 코드가 없으면(서버에 닿지 못함) 대신할 문장을 담음. HTTP 라이브러리의 원문 에러('Network Error', 시간 초과 문구)를 화면에 내보내지 않고 에러 코드도 띄우지 않음.
- 사람에게 나가는 문구는 화면의 말로 씀. 같은 동작의 버튼과 모달 이름과 알림이 같은 말이어야 함(생성 버튼이면 생성했습니다). 거절 문구는 짧게 끝내고 이유를 늘어놓지 않음. 프로젝트마다 용어(예: 리포트와 이력)가 정해져 있으면 그 문서를 따름.
- 권한이 없는 생성, 수정, 삭제 버튼은 메뉴 권한 컴포저블 하나로 숨김. 템플릿에서 권한 함수를 버튼마다 부르거나 컴포넌트마다 computed 를 새로 만들지 않음. 화면에서 권한을 한 번 더 검사하는 분기를 만들지 않음. 행 선택 같은 동작이 아닌 것은 권한에 묶지 않음.

## 확인 모달과 저장
- 확인 모달은 제목, 설명, 오류 제목(필수), 확인 라벨, 색, 실행 콜백으로 열고, 실행 콜백은 실패했을 때 사유 문자열만 돌려줌. 로딩과 닫기는 모달이 소유함. 액션은 throw 하지 않고 에러를 값으로 돌려주므로 try/catch 가 필요 없음.
- 오류 제목이 없으면 실패해도 화면이 그대로라 아무 말도 하지 않게 되므로 필수임. 실패하면 본문이 통째로 실패 화면(아이콘, 오류 제목, 사유)으로 바뀌고, 진행 중 화면도 본문을 통째로 갈아끼움. 진행 제목은 오래 걸리는 동작에만 줌.
- 설명의 줄바꿈은 호출부가 정함. 문장이 둘 이상이면 모달을 넓히지 않고 줄을 끊음.
- onConfirm 에는 넘기기만 하는 한 줄을 두고 분기가 있는 실행은 이름 붙여 밖에 둠. 이름은 스토어 액션과 겹치지 않게 화면에서 본 대상으로 지음.
- 입력을 받는 확인(비밀번호 초기화, 토큰 생성)은 전용 폼 모달로 두되 본문 위에 확인 창과 같은 묶음을 두어 확인 창으로 읽히게 함. 묻는 창과 결과를 알리는 창은 색이 다름.
- 저장 로직을 누가 갖는지는 모달이 자기 힘으로 할 수 있느냐로 정함. 스키마, 필드, 보낼 값, 부를 API 를 다 아는 전용 폼 모달은 스토어를 직접 부르고 close 이벤트로 결과를 돌려줌. 예 또는 아니오뿐인 확인 모달은 콜백 prop 을 받음. 전용 폼 모달에 콜백을 물리면 한 번 저장하는 데 다섯 번 오가고 필드 에러가 모달 밖으로 나가야 함.
- 부모는 모달의 결과 값만 보고(예: 'saved'이면 refresh) 모달을 이어 여는 흐름도 결과 값으로 함. 콜백으로 엮으면 중첩이 깊어짐.
- 모달 푸터의 버튼은 오른쪽 끝에 모으고 순서는 닫기 또는 취소, 보조 동작, 주 동작임. 삭제는 왼쪽 끝에 둠. 색으로 뜻을 싣는 것은 확인 창의 확인 버튼뿐이고 정해 둔 색의 뜻 표에 없는 색이 필요해 보이면 칠하기 전에 사용자에게 물음.

## 열자마자 한 건을 가져오는 화면
- 모달이 스스로 가져오고 부모가 미리 가져와 넘기지 않음. 목록과 상세는 다른 응답이고, 부모가 가져오면 모달이 뜰 때까지 화면이 죽어 있고 실패 시 다시 시도를 놓을 자리가 사라짐.
- prop 은 id 하나이고 행 객체를 넘기지 않음. 목록이 이미 값을 들고 있어도 쓰지 않으며 부분만 먼저 뜨는 최적화도 하지 않음. 상세 엔드포인트가 없으면 만듦.
- 상태는 useDetailFetch 가 들고 그리는 것은 AppFetchState 가 함. ref 세 개를 손으로 들지 않음.
- fetching(아직 못 가져옴)과 form.loading(저장이 도는 중)은 다른 말임. 수정 모달에는 둘이 같이 있음.
- 시작 시점은 호출부가 정함(onMounted). 가져온 뒤에 할 일을 끼울 수 있어야 하기 때문임. 다시 시도 버튼도 같은 함수를 불러야 함. 막는 실수: 실패 뒤 다시 시도에 성공하면 폼이 빈 채로 뜨는 일.
- 작업 뒤 같은 대상을 다시 받는 화면은 처음 받을 때만 스피너가 돌게 함(fetching 과 data 없음 조건). 그냥 fetching 을 넘기면 본문이 빠졌다 다시 붙어 안의 목록이 검색어와 필터를 잃음. 대상이 바뀌는 화면은 바꾸기 전에 data 를 비움.
- 목록 표는 AppFetchState 로 다시 감싸지 않음(표가 안에서 씀).

## 폼
- 입력 검증은 폼 컴포넌트와 스키마로 함. ref 로 에러를 직접 들고 검사 함수를 손으로 짜지 않음. 필드의 name 이 스키마 키와 같아야 에러가 그 필드에 붙음.
- 저장 로딩을 손으로 올렸다 내리지 않음. 폼 컴포넌트가 이미 들고 있고 제출 중에 입력칸을 전부 잠그는 일까지 함. 버튼이 폼 밖(모달 푸터)이면 템플릿 ref 로 읽음.
- 입력칸이 없어도 무엇을 골라 저장하는 화면은 폼으로 감쌈(스키마 없이도 됨). 검색칸은 폼 밖에 둠(안에 두면 Enter 가 저장을 보냄).
- 서버 에러는 폼의 setErrors 로 넣고 필드마다 에러 prop 을 손으로 엮지 않음. 서버 에러를 폼 에러로 바꾸는 변환은 전역 함수 하나(toFormErrors)로 함. 필드 에러면 칸에, 아니면 토스트로 보내는 분기와 문구는 모달마다 달라 모달에 남김. 백엔드가 필드별 리스트를 문자열 하나로 눌러 담으면 배열 검사가 항상 빗나가므로 변환에서 문자열로 바꿈. 다시 제출할 때는 지난 에러를 먼저 지움.
- 수정 폼에서 서버가 안 받는 값은 지우지 않고 생성 폼과 같은 자리에 잠긴 채로 둠. 지우면 보던 사람이 그 값을 찾으러 나가야 함. 값이 셀렉트여도 못 고르면 입력칸으로 라벨만 보여 주고 선택지를 받아오지 않음(선택지가 화면에 고정된 셀렉트는 예외). 잠근 칸은 탭 순서에서도 빠지므로 그 값을 꼭 읽어야 하면 상세에도 있어야 함.
- 고칠 수 있는 칸이 갈래마다 크게 다르면 수정 모달을 나눔. 한 폼에 칸마다 잠금 분기를 두면 폼이 두 역할을 하느라 읽히지 않음. 같은 행위를 갈래별로 나누면 갈래 이름은 화면이 이미 쓰는 말을 따르고 짝을 맞춤.
- 에러 prop 에 값을 명시적으로 넘기면 자동 검증 메시지를 덮어씀. 에러가 없을 때는 undefined 여야 하고 false 는 내장 검증까지 막음. 빈 문자열도 에러 있음으로 읽힘. null 이 올 수 있는 값을 `!!value` 로 바꾸지 않음(`value ? true : undefined`로 씀).
