# cog-code-writer

코드를 쓸 때 지키는 기본 규칙. 각 규칙에는 막으려는 실수를 함께 적음. 근거 없는 규칙은 지켜지지 않기 때문임.

## 1. 주석과 독스트링
- 지우면 누가 무엇을 잘못하는지 말할 수 있는 한 줄만 적음.
  - 적는 대상은 지우면 깨지는 순서, 숫자의 근거, 코드만 봐서는 모르는 이유
  - 적지 않는 대상은 동작을 되풀이하는 설명, 지난 사연, 문서에 있는 정책, 프레임워크가 당연히 하는 일
- 함수와 테스트의 독스트링은 기본으로 쓰지 않음. 이름과 코드가 말함.
- 정책이 적힌 독스트링은 지우기 전에 문서에 있는지 확인. 없으면 문서로 옮긴 뒤 지움.
- 사람이 지운 주석은 되살리지 않음. 남이 쓴 코드의 주석 문제는 고치지 않고 알림.
- 중요한 규칙은 문장으로 적지 않고 린트나 테스트로 강제. 문장은 아무것도 막지 못함.
- 막는 실수: 코드가 바뀔 때 혼자 낡아서 읽는 사람을 속이는 주석.
- 세부와 예시: `references/comments.md`

## 2. 예시와 목업 데이터
- 실제 사람의 이름, 아이디, 사번, 연락처 사용 금지. alice, bob 같은 가상 이름 사용.
- 막는 실수: 목업에 쓴 실명이 예시로 복사되어 수백 곳으로 퍼지는 일.

## 3. 함수와 파일
- 공용 자리로 올리는 기준은 둘 이상이 쓰는지 여부. 한 곳만 쓰면 그 기능 안의 성격에 맞는 파일에 둠.
- 비슷한 코드는 두 곳이면 두 번 쓰고 셋째가 생기면 뺌. 이미 같은 함수가 복사돼 있으면 시점이 아니라 자리 문제이므로 올림.
- 줄이 길거나 두 줄이 비슷하다는 이유만으로 내부 헬퍼 함수를 만들지 않음.
- 한 함수가 서로 다른 단계를 여럿 하면 부르는 곳이 하나여도 단계마다 나눔. 기준은 길이가 아니라 하는 일의 수.
- 파일은 하는 일(formatters, validators)로 나눔. 대상(account, order)으로 나누지 않음.
- 남에게 넘기는 함수(콜백, map 인자) 안에 분기나 계산을 넣지 않음. 이름을 붙여 밖에 두고 넘기기만 함. 한 번 쓰는 계산은 지역 변수에 둠.
- return 줄이나 인자 안에서 직접 만든 함수의 결과를 바로 넘기지 않음. 변수에 담은 뒤 사용. 언어 기본 함수와 프레임워크 관용구는 예외.
- 프레임워크 기능은 관례라서 들이지 않음. 얻는 것을 댈 수 있을 때만 사용.
- 가장 단순한 답을 먼저 냄. 더 복잡한 쪽이 필요한 이유를 구체적으로 댈 수 없으면 단순한 쪽 선택.
- 막는 실수: 공용 자리가 서랍이 되는 일, 복사한 두 곳 중 한 곳만 고쳐서 조용히 어긋나는 일.
- 세부와 예시: `references/structure.md`

## 4. 한 가지는 한 곳에
- 원본에서 자동으로 나오는 값은 스스로 규칙을 갖지 않음. 규칙은 하나로 봄.
- 프레임워크가 자동으로 해 주는 일을 손으로 다시 짜고 있다면 앞 단계에서 무언가 뺀 신호. 메우기 전에 왜 비었는지 확인.
- 새 이름을 짓기 전에 같은 개념을 이미 정한 말이 있는지 검색. 한 개념은 한 이름. 참과 거짓 값은 is_ 또는 has_ 꼴.
- 막는 실수: 같은 규칙이 두 곳에 있어서 한쪽만 고치다가 조용히 어긋나는 일.

## 5. 옮기고 이름을 바꾼 뒤 문서 확인
- 링크, 본문의 경로, 목차와 실제 파일(양방향), 절 번호 참조, 옛 경로를 모두 확인. 하나만 건너뛰어도 조용히 낡음.
- 숫자와 목록은 코드가 원본. 문서끼리 맞추지 않고 코드에서 다시 뽑음. 언제 대조했는지 적음.
- 막는 실수: 틀린 문서는 없는 문서보다 나쁨. 읽는 사람이 믿고 움직임.
- 세부: `references/verification.md`

## 6. 확인하고 끝냄
- 테스트를 썼으면 지키려는 코드를 일부러 되돌려 그 테스트가 실제로 실패하는지 확인. 통과하는 테스트는 아무것도 증명하지 않음.
- 맞아 보인다는 느낌으로 끝내지 않음. 화면은 좌표와 계산된 스타일, 성능은 쿼리 수, 동작은 저장된 값으로 확인.
- 새로 만든 것보다 이전 동작이 그대로인지 먼저 확인.
- 막는 실수: 잘 돌아가는 것 같다는 느낌으로 넘어간 뒤 실전에서 깨지는 일.
- 세부: `references/verification.md`
