# 함수와 파일 세부

## 올리는 기준
- 한 곳만 쓰면 공용 자리로 올리지 않고 그 기능 안에서 성격에 맞는 파일에 둠.
- 둘 이상이 쓰면 공용 자리로 올림. 공용 자리는 쓰는 범위가 정함. 같은 앱 안이면 그 앱의 공용 자리, 다른 앱 둘 이상이거나 앱을 모르는 성격이면 전역.
- 비슷한 코드를 함수로 빼는 시점은 따로임. 두 곳이 비슷할 뿐이면 두 번 쓰고 셋째가 생기면 뺌.
- 이미 똑같은 함수가 두 곳에 복사돼 있으면 시점이 아니라 자리 문제라서 위 기준대로 올림.
- 한 곳만 쓰는 헬퍼까지 끌어오면 공용 자리가 서랍이 됨. 반대로 두 곳에 같은 함수를 복사하면 한 곳만 고치고 다른 곳을 잊어서 그 화면만 조용히 다르게 동작함.
- 뺄 자리를 못 정하겠다는 것은 아직 뺄 때가 아니라는 신호. 자리를 찾느라 설계를 키우고 있으면 멈춤.

## 예외
- 한 함수가 서로 다른 단계(거르기, 맵핑, 비교)를 여럿 하면 부르는 곳이 하나여도 단계마다 나눔. 고칠 때 찾는 곳이 다르기 때문임. 바깥 함수는 단계를 차례로 부르기만 하고 위에서 아래로 읽힘.
- 각 동작의 짧은 입력 확인은 셋이어도 그 자리에 둠. 값을 꺼내 모양을 보고 한 번 조회하는 몇 줄은 동작마다 위에서 아래로 읽혀야 함.

## 파일은 성격으로 나눔
- formatters, validators 처럼 무엇을 하는지로 가름. account, order 처럼 무엇을 다루는지로 가르지 않음.
- 둘을 섞으면 갈 곳이 둘이 되어 사람마다 다르게 넣음. 성격으로 나눌 때는 이웃이 생길 이름인지 확인. 함수 하나를 위해 만든 파일은 계속 하나짜리로 남음.

## 함수 안의 로직
- 남에게 넘기는 함수(콜백, map, computed 인자) 안에 분기나 계산을 품지 않음. 이름을 붙여 밖에 두고 바깥은 부르기만 함.
- 넘기기만 하는 한 줄(선언)은 그 자리에 둠. 이름을 붙여 밖으로 빼면 읽는 사람이 한 번 더 건너가야 함.
- 한 함수 안에서 한 번 쓰는 계산은 그 자리에 둠. 설명이 필요하면 지역 변수 이름으로 줌.

나쁜 예: 콜백 안에 분기가 들어 있음
```ts
const columns = props.columns.map(col => {
    const meta = { ...col.meta };
    if (meta.align === 'center') {
        meta.class = { ...meta.class, td: 'text-center' };
    }
    return { ...col, meta };
});
```

좋은 예: 로직은 이름을 붙여 밖에 두고 바깥은 부르기만 함
```ts
const toAlignedMeta = (meta) => (meta.align === 'center'
    ? { ...meta, class: { ...meta.class, td: 'text-center' } }
    : meta);

const columns = props.columns.map(col => ({ ...col, meta: toAlignedMeta(col.meta) }));
```

## 호출을 겹치지 않음
- return 줄이나 함수 인자 안에서 직접 만든 함수의 결과를 바로 넘기지 않음. 변수에 담아 다음 줄에서 사용.
- 막는 대상은 우리가 만든 함수의 결과임. 언어 기본 함수와 프레임워크 관용구는 인자 안에 그대로 둠.

나쁜 예
```python
rows = reset_passwords(user.id, generate_password(), source="MANUAL")
```

좋은 예
```python
new_password = generate_password()
rows = reset_passwords(user.id, new_password, source="MANUAL")
```

## 단순한 답을 먼저
- 더 복잡한 쪽이 왜 필요한지 구체적으로 댈 수 없으면 단순한 쪽으로 감.
- 프레임워크 기능도 관례라서 들이지 않음. 우리가 실제로 얻는 것을 댈 수 있을 때만 사용.
