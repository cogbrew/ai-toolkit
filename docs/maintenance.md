# 지침·스킬 작성·갱신 안내

스킬(`SKILL.md`)이나 지침 파일(`AGENTS.md`, `CLAUDE.md`)을 새로 만들거나 고치거나 정리하는 요청을 받으면 읽는다. README 수정과 코드 작성에는 읽지 않는다.

이 문서는 아래 뜻으로만 용어를 쓴다.
- 본체: 가져온 프로젝트 전체. 래퍼 폴더의 `project/` 에 둔다.
- 래퍼 폴더(wrapper): 폴더 바로 아래에 `SKILL.md` 가 없는 가져온 스킬을 `project/` 로 담고 진입 파일을 곁에 둔 스킬 폴더. 위치는 `ai-agents/skills/<스킬>/` 다.
- 진입 파일: 래퍼 폴더 안에서 `project/` 의 본체를 가리키는 짧은 `SKILL.md`.
- 사본: 고치기 전에 스크래치패드에 만든 복사본.
- 확인: 공식 문서나 파일을 읽어 사실을 알아내는 일.
- 시험: 실제로 실행해 동작을 관찰하는 일.

## 1. 절차

루트 `AGENTS.md` 3번은 가져온 스킬을 추가하는 절차이고, 이 절은 지침과 스킬을 쓰거나 고치는 절차다.

1. 고칠 문서의 사본을 만들고 사본에서 먼저 고친다.
2. 도구별 공식 문서를 확인한다(2·3절 기준, 루트 `AGENTS.md` 5번 표).
3. 사본을 시험한다(4절).
4. 바뀐 줄을 사용자에게 보여 주고 승인받은 뒤 저장소 파일에 반영한다.
5. 커밋과 push 는 사용자가 말할 때만 한다.
6. 전역 링크는 사용자가 만들고 바꾼다.
7. 반영 뒤 루트 `AGENTS.md` 5번 표의 확인 상태와 이 문서 5절을 갱신한다.

## 2. 지침 문서 작성 기준

`ai-agents/AGENTS.md` 와 도구별 지침 파일에 적용한다. 근거가 「공식 문서」인 항목은 해당 도구 문서에서 확인한 것이다.

| 기준 | 근거 |
|---|---|
| 한 파일은 Claude 200줄 이하, Antigravity 24 KB 이하, Codex 합계 32 KiB 이하 | 공식 문서 |
| 주제별 제목과 불릿으로 구성하고 긴 문단은 쓰지 않는다 | Claude 공식 문서 |
| 항목은 구체적이고 검증 가능하게 쓴다. 예: 「Format code properly」 대신 「Use 2-space indentation」 | Claude 공식 문서 |
| 서로 부딪치거나 모호한 지시를 두지 않는다. 새 규칙을 넣을 때 기존 규칙과 충돌하는지 먼저 확인한다 | Claude 공식 문서(충돌 시 임의로 하나를 고름) |
| 여러 단계 절차와 특정 작업에만 필요한 내용은 지침이 아니라 별도 문서나 스킬에 둔다 | Claude 공식 문서 |
| 반드시 지켜야 하는 것은 지침 문구에 더해 hook·권한 설정으로 강제한다. 지침은 강제가 아니라 맥락이다 | Claude 공식 문서 |
| 지켜야 할 행동과 예외를 함께 적는다 | Codex 공식 문서(코드 리뷰 맥락) |
| 같은 개념에는 같은 말만 쓰고, 비유는 풀어 쓴다 | 판단(시험에서 실패는 없었음) |
| 반영하기 전에 사본을 시험한다 | 이번에 한 방식 |

- 명사형 종결 통일은 개인 규칙 문서(`ai-agents/AGENTS.md`)에 적용한다. 저장소 작업 문서(루트 `AGENTS.md`, 이 문서)는 서술형으로 쓴다.
- 다른 파일을 불러오는 문법은 도구마다 다르다. Claude 는 `@경로`(불러오는 파일 기준 상대 경로), Antigravity 는 `@[라벨](경로)`, Codex 는 문법이 없다.

## 3. 스킬 작성 기준

직접 만드는 스킬에 적용한다. 가져온 스킬(`slop-rewrite` 등)은 내부 구조를 바꾸지 않는다.

- 작성 도구: Claude 의 `skill-creator` 스킬을 이름으로 호출한다. 가져온 스킬에는 쓰지 않는다(폴더 구조를 바꾸기 때문). 경로에 해시가 있어 경로는 적지 않는다.
- 형식: `SKILL.md` 머리말의 `name`·`description` 만으로 세 도구가 읽는다. `name` 은 폴더 이름과 같게 둔다.
- 이름: 직접 만드는 스킬의 폴더 이름과 `name` 은 `cog-` 로 시작하는 소문자-하이픈으로 정한다. 가져온 스킬은 이름을 바꾸지 않으며, 접두사가 없으면 가져온 스킬이다.
- `description`: 무엇을 하는지, 언제 쓰는지, 쓰지 않는 경우를 쓴다. 핵심 용도와 사용자가 쓸 법한 키워드를 앞에 둔다.
  - Claude 는 목록에서 1,536자까지만 보여 준다.
  - Codex 는 목록 예산(컨텍스트의 2% 또는 8,000자)을 넘으면 설명부터 줄인다.
  - Antigravity 는 3인칭을 권한다.
- 본문: Claude 기준 500줄 이하. 상세 자료는 `references/` 로 나누고 본문에 언제 읽을지 적는다. 스킬 하나는 한 가지 일만 한다.
- 문체: 명령형으로 쓰고, 강한 금지어보다 이유를 설명한다.
- 전역 연결: 래퍼 폴더의 진입 파일에는 `name`, `description`, `project/` 를 가리키는 상대경로만 둔다. 전역 에이전트가 읽는 것은 진입 파일의 `description` 이므로 본체의 모드와 제외 조건을 거기에 담는다. 본체 모드를 넣은 `description` 이 호출을 늘렸다(Claude, 1회 시험).
- 시험: 호출되어야 할 질문과 호출되면 안 되는 질문을 목록으로 만들어 호출 여부를 본다(4절).

도구별 폴더 링크 인식(2026-11-11 기준)

| 도구 | 인식 | 근거 |
|---|---|---|
| Claude Code | 인식됨 | 시험(일반 폴더와 링크 모두) |
| Codex | 미시험 | 공식 문서가 링크 폴더 지원을 명시 |
| Antigravity | 미시험 | 문서에 링크 언급 없음 |

## 4. 시험 방법

Claude 기준이고 2026-11-11 에 확인한 옵션이다. 버전에 따라 달라질 수 있다.

- 지침 따름 시험: 스크래치패드에 빈 폴더를 만들고 시험할 지침을 그 폴더의 `CLAUDE.md` 로 둔다. `claude -p` 로 실행하고, 전역 `CLAUDE.md` 는 `--settings` 의 `claudeMdExcludes` 로 제외하며, 도구는 `--tools ""` 로 끈다.
- 로드 확인은 「지침을 인용해 보라」가 아니라 표식 문장(임의의 암구호)으로 한다. 인용 요청은 믿을 수 없었다.
- 서브에이전트(Agent 도구)는 시험에 쓰지 않는다. 전역 지침을 물려받아 시험이 오염된다.
- 도구를 끄면 「확인 후 답변」 규칙 때문에 안을 내지 않는다. 시험 과제에 필요한 내용을 프롬프트에 넣는다.
- 조직 관리자 지침은 제외되지 않는다.
- 스킬 호출 시험: 본문이 확인 문구 한 줄인 껍데기 스킬로 `description` 만 바꿔 호출 여부를 본다. 스킬은 도구로 불리므로 도구를 끄지 않는다. 응답 전체가 확인 문구 한 줄일 때만 호출로 센다. 응답이 문구를 인용만 한 것은 호출이 아니다.
- 문서 읽음 시험: 문서 안에 「응답 첫 줄에 표식을 쓴다」는 규칙을 두고 표식이 나오는지 본다. 응답이 쓰기 실패 안내로 시작하면 표식이 첫 줄에 없어도 문서를 읽은 경우가 있으므로, 응답에 문서 이름이 언급됐는지도 함께 본다.
- 질문당 1~3회 실행하므로 한 번의 차이로 결론을 내지 않는다.
- 연결 스크립트 시험: `HOME` 을 스크래치패드의 가짜 홈 폴더로 바꿔 계획 출력, `--apply`, 재실행, `--backup` 을 차례로 돌려 링크, 기존 항목 보존, 멱등성을 확인한다. 실제 홈 폴더에는 `--apply` 를 쓰지 않는다. 2026-11-11 에 이 방식으로 시험했다.
- Codex(`codex exec`)와 Antigravity(`agy -p`) 시험은 사용자가 환경을 준비해 준 뒤에만 한다.

## 5. 결정 기록 (2026-11-11)

- 폴더 이름 `ai-agents/`: 도구별 폴더를 한 곳에 묶기 위해 정했다. `agents/` 는 서브에이전트 폴더와 혼동되고, `global/`·`home/`·`shared/`·`rules/` 는 의미가 맞지 않거나 도구가 쓰는 이름과 겹쳐 제외했다.
- 스킬은 `ai-agents/skills/` 한 곳에 둔다: 최상위 `skills/` 를 없애고 `ai-agents/` 가 지침과 스킬을 함께 담는다. 세 도구가 같은 `SKILL.md` 형식을 읽으므로 진입 파일을 도구마다 두지 않고 한 벌만 둔다. 한 도구에만 쓰는 스킬은 `ai-agents/<도구>/skills/` 에 둔다.
- 래퍼 폴더 방식: `slop-rewrite` 스크립트가 자기 위치에서 루트를 계산해 내부 구조를 바꿀 수 없다. 그래서 가져온 프로젝트를 `project/` 에 통째로 담고 진입 파일을 곁에 둔다. 상대경로만 쓰므로 저장소를 옮겨도 동작한다. Claude 에서 인식, 상대경로 따라가기, 스크립트 실행, 목록에 중복 없음을 시험했다(2026-11-11).
- 연결 스크립트(`scripts/install.sh`): 기본은 계획만 출력하고 `--apply` 로 실행한다. 스킬 하나마다 링크하며 도구 폴더 전체는 링크하지 않는다. 이미 있는 항목은 덮어쓰지 않고 `--backup` 일 때만 옮겨 둔다. 삭제 명령은 쓰지 않는다. 별칭 `~/.ai-toolkit`(저장소 위치) 도 만든다. 도구별 경로와 예약 이름은 `scripts/targets.conf` 에 둔다.
- 이름 규칙: 직접 만든 스킬만 `cog-` 접두사를 붙이고, 가져온 스킬(`slop-rewrite`, `taste-builder`, `styleguide-builder`)은 이름을 유지한다. 기존 `my-*` 스킬 4개를 가져올지는 구조가 정해진 뒤에 다시 정한다.
- 공통 지침은 `ai-agents/AGENTS.md` 한 파일: 도구 전용 줄이 없어 한 파일로 시작했다. `ai-config` 의 공통 지침 49줄을 문체만 명사형으로 바꿔 옮겼다.
- `ai-config` 는 이전이 끝난 뒤 쓰지 않는다.
- 다루는 도구: Claude Code, Codex, Antigravity(앱·CLI). Antigravity IDE 는 쓰지 않는다. Gemini CLI 는 Antigravity CLI 로 대체되어 다루지 않는다.
- 이 문서를 스킬이 아니라 참조문서로 둔 이유: Claude 시험(질문당 1회)에서 안내를 보고 문서를 읽은 비율이 4/4, 스킬 호출은 2/4 였다. 세 도구 호환과 폴더 구조의 단순함도 근거다.
- 루트 `AGENTS.md` 7번의 안내 문구는 세 차례 고쳤다. 처음 문구는 「새 스킬 추가」 요청에서 문서를 읽지 않았고, 두 번째 문구는 「스킬 만들어줘」 같은 작업 요청에서 읽지 않았다. 작업 시점(「…하는 요청을 받으면, 파일을 쓰기 전에」)을 명시한 지금 문구에서 작업 요청 3/3 은 읽었고 무관한 요청 3/3 은 읽지 않았다.

## 6. 아직 정하지 않은 것

- 안내 문구 시험은 질문당 1회, Claude 한 모델이다. 읽는 비율이 이 결과보다 낮을 수 있고, Codex·Antigravity 는 시험하지 않았다.
- 공통 지침 7행 「미정으로 보고 제외」의 의미, 용어 변주(안·계획·설계, 승인·확인), 따옴표·가운뎃점·마침표 통일: 따름 시험에서 실패가 나오지 않아 보류했다.
- 「스스로 커밋 금지」「비밀 정보 금지」를 hook·권한 설정으로도 강제할지.
- 공통 지침을 각 도구의 전역 위치에 연결하는 방식(도구별 파일에서 참조할지, 직접 링크할지).
- Antigravity 의 전역 규칙 파일 이름.
- 구현 전(설계는 정함): 다른 프로젝트에서 이 문서를 읽게 하는 전역 지침 안내(`ai-agents/AGENTS.md` 에 2줄).
- 비대화형 시험에서 작업 폴더 밖 읽기와 `python` 실행은 승인이 필요했다. `ai-toolkit` 폴더를 읽기 허용 폴더로 등록할지는 사용자가 정한다(설정 변경).
- Codex·Antigravity 에서의 스킬 인식과 `description` 호출 시험.
